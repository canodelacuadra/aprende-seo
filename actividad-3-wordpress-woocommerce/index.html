Antes de empezar

Esta actividad reutiliza la marca y los contenidos de las dos anteriores, pero cambia la tecnología: pasas de HTML estático a WordPress y añades una tienda WooCommerce. El objetivo no es solo «que funcione», sino entender qué hace el CMS, qué hace el plugin SEO y qué sigue dependiendo de ti.

Objetivos de aprendizaje

  • Configurar WordPress para que sea rastreable e indexable.
  • Elegir una estructura de URL legible y estable.
  • Instalar y configurar Yoast SEO sin duplicar funciones.
  • Optimizar páginas, entradas y medios con títulos y metas propios.
  • Organizar categorías y etiquetas sin generar contenido fino.
  • Controlar autor, fecha, paginación y fuentes de duplicado.
  • Montar una tienda WooCommerce con fichas, variaciones, filtros y reseñas bien resueltas.
  • Medir el rendimiento y comparar el SEO en HTML frente a WordPress.

Qué necesitas

  • LocalWP (o un WordPress local equivalente) con una instalación nueva.
  • El tema GeneratePress, ya trabajado en clase.
  • El plugin Yoast SEO y el plugin WooCommerce.
  • Chrome con DevTools y Lighthouse.
  • Opcional: un hosting o servicio de publicación si quieres probar Search Console.

Local no es Internet

En LocalWP la web funciona en tu ordenador, pero Google no puede acceder a ella. Puedes practicar toda la configuración y medir con Lighthouse, pero la verificación en Search Console y el envío del sitemap solo tienen sentido cuando el sitio esté publicado en una URL accesible. En la entrega se explica qué parte es local y qué parte está publicada.

No conviertas la práctica en una carrera de plugins

Cada plugin añade peticiones, CSS, JavaScript y mantenimiento. Para esta actividad bastan GeneratePress, Yoast SEO y WooCommerce. Si añades otro, debes poder justificar qué problema resuelve y qué coste tiene.

Conceptos clave

WordPress tiene su propio vocabulario. Este es el que necesitas para no perderte.

Muchos términos se parecen a los de las actividades anteriores, pero aquí cambia quién hace el trabajo: el CMS, el tema, el plugin o tú. Cada definición enlaza al paso donde se aplica.

CMS
Sistema de gestión de contenidos: permite publicar y organizar contenido sin escribir HTML a mano. WordPress es el CMS que usamos (paso 1).
Tema
Capa visual y de plantillas del CMS. Decide la estructura HTML que se genera y qué se puede cambiar sin tocar código (paso 1).
Plugin
Extensión que añade funciones al CMS. Cada plugin puede cargar CSS y JavaScript, así que conviene instalar solo los necesarios (paso 4).
Yoast SEO
Plugin que gestiona títulos, metadatos, sitemap y análisis on page. Ayuda, pero no sustituye al criterio ni garantiza posiciones (paso 4).
Enlace permanente
Estructura de URL que WordPress aplica a entradas y páginas. Se configura una vez y conviene no cambiarla después (paso 3).
Slug
Parte final de la URL que identifica un contenido concreto. Debe ser corto, en minúsculas, sin tildes y con guiones (paso 3).
Taxonomía
Sistema de clasificación de contenidos. En WordPress las principales son las categorías y las etiquetas (paso 8).
Categoría
Agrupación amplia y estable del blog. Debe tener contenido propio y no solaparse con otras categorías (paso 8).
Etiqueta
Clasificación libre y transversal. En exceso genera archivos con poco contenido y duplicados (paso 8).
Contenido fino
Páginas con poco valor que no responden a una intención clara. Los archivos de etiquetas y las paginaciones vacías son el caso típico (paso 8).
Autor y fecha
Datos que contextualizan una entrada y aportan confianza. Deben ser visibles y coherentes con los datos estructurados (paso 9).
Paginación
División de un listado en varias URL. Debe poder rastrearse y no competir con el contenido principal (paso 9).
Contenido duplicado
El mismo contenido accesible desde varias URL. Se corrige con canonical, redirección o noindex, según el caso (paso 10).
WooCommerce
Plugin de comercio electrónico para WordPress. Añade productos, carrito, pedidos y sus propias plantillas (paso 14).
Producto variable
Producto con varias versiones, por ejemplo por talla o color. Cada variación puede tener precio y stock propios (paso 16).
Atributo y variación
El atributo es la característica (color) y la variación es el valor concreto (azul). Juntos definen las opciones de un producto variable (paso 16).
Faceta
Filtro de una tienda que combina atributos y genera nuevas URL. Sin control multiplica páginas de bajo valor (paso 17).
Product, Offer y Review
Tipos de schema para una ficha de producto: el producto, su oferta de precio y sus reseñas (paso 18).
AggregateRating
Propiedad de schema que resume la media de valoraciones. Requiere reseñas visibles y reales en la página (paso 18).
LocalWP
Aplicación que crea un WordPress local sin configurar un servidor. Sirve para practicar sin publicar (paso 1).

01 Preparar WordPress y la estructura

Antes de tocar SEO, la web debe tener las páginas y entradas correctas.

Objetivo del paso

Crear la instalación, activar GeneratePress y dejar publicada la estructura mínima del proyecto.

  1. Crea un sitio nuevo en LocalWP y anota la ruta y el dominio local.
  2. Completa el instalador de WordPress con el nombre TecnoSerprofes.
  3. En Apariencia → Temas, instala y activa GeneratePress.
  4. Crea las páginas y entradas de la tabla.
  5. En Apariencia → Menús, crea el menú principal con Inicio, Servicios, Blog y Contacto.
  6. Asigna la página de Inicio como portada estática en Ajustes → Lectura.

Contenido real, aunque sea ficticio

No publiques entradas vacías con «Lorem ipsum». Cada página debe tener al menos varios párrafos con información útil y coherente con TecnoSerprofes. El SEO se evalúa sobre contenido, no sobre marcadores de posición.

02 Comprobar la visibilidad del sitio

Un solo ajuste puede dejar toda la web fuera de Google.

Objetivo del paso

Verificar que WordPress no está pidiendo a los buscadores que no indexen el sitio.

  1. Ve a Ajustes → Lectura.
  2. Busca la opción Visibilidad en los motores de búsqueda.
  3. Comprueba que no está marcada la casilla «Desanimar a los motores de búsqueda a indexar este sitio».
  4. Guarda los cambios.
  5. Si usas Yoast, revisa también Yoast SEO → Ajustes → General → Visibilidad del sitio.

Cuando esa opción está activa, WordPress añade noindex y bloquea la indexación del sitio. Es habitual olvidarla activada tras pasar de un entorno local a producción, y entonces nada de lo que hagas después aparece en Google. 

<!-- Señal de que el sitio está desanimado para los buscadores -->
<meta name="robots" content="noindex, nofollow">

Cómo comprobarlo de verdad

  • Abre la portada y usa Ver código fuente: no debe aparecer noindex.
  • Revisa https://tu-dominio/robots.txt: no debe contener Disallow: /.
  • En Search Console, la inspección de URL debe indicar que la página se puede indexar.

Dos interruptores, no uno

WordPress y Yoast pueden bloquear la indexación por separado. Si desactivas uno y el otro sigue activo, el sitio continúa fuera. Comprueba siempre el HTML servido, no solo el panel.

Evidencia

Captura de Ajustes → Lectura y del código fuente sin noindex.

03 Configurar los enlaces permanentes

La estructura de URL se decide una vez y se cambia con cuidado.

Objetivo del paso

Elegir una estructura de URL legible con el slug y comprobar cómo quedan páginas, entradas y productos.

  1. Ve a Ajustes → Enlaces permanentes.
  2. Selecciona Nombre de la entrada (/%postname%/).
  3. Guarda los cambios.
  4. Comprueba la URL de una página y de una entrada.
Qué cambia con cada estructura
EstructuraEjemploValoración
Simple/?p=25No dice nada al usuario ni al buscador.
Día y nombre/2026/11/15/elegir-portatil/Añade fechas que envejecen el contenido.
Nombre de la entrada/elegir-portatil/Legible, corta y estable. Recomendada.
Personalizada/blog/%postname%/Útil si separas blog y tienda, pero alarga la URL.

En WooCommerce, los productos tienen su propia base. En WooCommerce → Ajustes → Productos → Enlaces permanentes puedes elegir algo como /producto/ o /tienda/%product_cat%/. No mezcles productos y entradas en la misma base si puedes evitarlo.

Cambiar enlaces después de publicar

Si ya tienes URL indexadas y cambias la estructura, las antiguas dejan de existir. WordPress intenta redirigir algunas, pero no todas. Lo correcto es planificar la estructura antes de publicar y, si hay cambios, crear redirecciones 301 una a una.

Comprueba

  • Las URL son minúsculas, sin acentos y con guiones.
  • No aparece ?p= en ninguna URL pública.
  • Páginas, entradas y productos tienen bases distintas y coherentes.

Evidencia

Captura de Ajustes → Enlaces permanentes y de dos URL resultantes.

04 Instalar y configurar Yoast SEO

El plugin automatiza tareas, pero no decide por ti.

Objetivo del paso

Instalar Yoast SEO, completar los datos del sitio y revisar qué genera automáticamente.

  1. Ve a Plugins → Añadir nuevo.
  2. Busca Yoast SEO, comprueba que es el plugin oficial y pulsa Instalar ahora.
  3. Pulsa Activar y completa la configuración inicial.
  4. Revisa estas secciones:
    • General → Datos del sitio: nombre, nombre alternativo, logo y perfiles sociales.
    • General → Visibilidad del sitio: debe permitir la indexación.
    • Apariencia en el buscador: plantillas de título y meta description.
    • Tipos de contenido y Taxonomías: qué se indexa y qué no.
    • Sitemaps: activados.

No instales Yoast y Rank Math a la vez. Ambos generan títulos, canonical, sitemap y schema, y acabarás con etiquetas duplicadas y señales contradictorias. Elige uno y desactiva el otro.

05 Optimizar la página de inicio

Una keyword principal, un título propio y una descripción útil.

06 Optimizar Servicios y Contacto

Cada página tiene su propia intención y su propio metadato.

Objetivo del paso

Repetir el proceso en las páginas de Servicios y Contacto sin copiar títulos ni descripciones.

Títulos y descripciones de ejemplo
PáginaTítulo SEOMeta description
Servicios Servicios de reparación de ordenadores | TecnoSerprofes Conoce nuestros servicios de mantenimiento, reparación y puesta a punto de ordenadores y portátiles.
Contacto Contactar con TecnoSerprofes | Reparación informática Contacta con TecnoSerprofes para solicitar información sobre nuestros servicios de reparación y mantenimiento informático.

No copies el mismo título y la misma descripción en todas las páginas. Si dos páginas comparten metadatos, el buscador no puede distinguir qué ofrece cada una y ambas pierden relevancia.

Qué debe tener cada página

  • Un h1 distinto y alineado con la intención.
  • Contenido suficiente: no vale una línea y un formulario.
  • Enlaces internos hacia servicios concretos y hacia el blog.
  • En Contacto, datos reales o claramente ficticios, sin inventar direcciones que no existan.
  • Un formulario que funcione y una página de agradecimiento con noindex.

Páginas de agradecimiento

La página que se muestra tras enviar un formulario no aporta valor en buscadores y puede recibir tráfico residual. Configúrala con noindex desde Yoast y no la incluyas en el menú.

08 Categorías, etiquetas y taxonomías finas

Cada archivo de taxonomía es una página más que puede competir o molestar.

Objetivo del paso

Organizar el blog con categorías útiles y decidir qué hacer con las etiquetas y archivos con poco contenido.

Categorías y etiquetas no son lo mismo
AspectoCategoríasEtiquetas
EstructuraJerárquica: pueden tener subcategorías.Plana y transversal.
FunciónAgrupan el contenido principal.Detallan temas concretos.
CantidadPocas y estables.Pueden multiplicarse sin control.
Riesgo SEOArchivos duplicados si no hay descripción.Páginas finas y contenido duplicado.

Para el proyecto, crea estas categorías:

  • Consejos informáticos
  • Mantenimiento
  • Equipos informáticos

Qué hacer con las etiquetas

  • Úsalas solo si aportan una navegación real.
  • No crees una etiqueta por cada palabra clave.
  • Si un archivo de etiqueta tiene una sola entrada y poco texto, valora noindex o elimina la etiqueta.
  • En Yoast → Ajustes → Taxonomías puedes desactivar la indexación de etiquetas.

La nube de etiquetas no es una estrategia SEO

Una lista de veinte etiquetas en el pie no ayuda al usuario ni al buscador. Genera decenas de URL con listados casi idénticos. Menos etiquetas, mejor elegidas, es la opción sensata.

09 Autor, fecha y paginación

Los archivos automáticos de WordPress no siempre merecen estar en Google.

Objetivo del paso

Decidir qué hacer con los archivos de autor y fecha, y revisar la paginación del blog.

Archivos de autor

Si el blog tiene un solo autor, el archivo de autor repite el listado del blog y no aporta nada. En ese caso se aplica noindex. Si hay varios autores con biografía y contenido propio, pueden indexarse y enlazarse desde cada artículo.

Archivos por fecha

Los archivos de mes o año generan listados duplicados y de poco valor para las búsquedas. Se recomienda noindex, salvo que el sitio sea un archivo histórico con valor propio.

Paginación

  • Mantén la paginación rastreable y con enlaces claros entre páginas.
  • No apliques noindex a las páginas 2, 3… si son el único camino hacia entradas antiguas.
  • Cada página paginada debe tener su canonical a sí misma, no a la página 1.
  • Evita el desplazamiento infinito sin paginación real: el bot no hace scroll.
  • Los enlaces rel="next" y rel="prev" ya no los usa Google, pero ayudan a la navegación.

Dónde se configura en Yoast

En Yoast SEO → Ajustes → Tipos de contenido → Entradas puedes desactivar la indexación de los archivos de autor y fecha. Comprueba después el HTML: debe aparecer noindex solo en esos archivos, no en las entradas.

10 Revisar el contenido duplicado

WordPress crea URL que no sabías que existían.

Objetivo del paso

Localizar las fuentes típicas de duplicados y decidir canonical, noindex o redirección.

Fuentes habituales de duplicados en WordPress
FuenteEjemploQué hacer
Adjuntos/tecnico-reparando-ordenador/Redirigir al archivo o a la entrada; evitar que se indexen.
Feeds/feed/No indexar; son para lectores, no para búsquedas.
Búsqueda interna/?s=portatilnoindex y bloquear parámetros infinitos.
Parámetros?utm_source=..., ?fbclid=...Canonical a la URL limpia.
Barra final/servicios y /servicios/Elegir una y redirigir la otra.
HTTP/HTTPS y wwwCuatro variantes del dominioRedirigir todo a la versión canónica.

Cómo detectarlo

  1. Busca en Google site:tu-dominio y revisa qué aparece.
  2. En Search Console, consulta Páginas y agrupa por «Duplicada, Google ha elegido una versión diferente».
  3. En Screaming Frog, revisa Canonicals y Duplicate.
  4. Revisa en Yoast si los adjuntos están redirigidos y si la búsqueda interna está desindexada.

No bloquees lo que necesitas rastrear

Si bloqueas una URL en robots.txt, el bot no podrá leer su noindex. Para excluir del índice, usa noindex y deja la URL rastreable. Reserva robots.txt para rutas que no deben rastrearse nunca.

12 Sitemap XML y datos estructurados

Deja que el plugin genere lo que ya sabe generar y revisa que no se duplique.

Objetivo del paso

Localizar el sitemap de Yoast, comprobar su contenido y validar los datos estructurados del sitio.

Sitemap

  1. Ve a Yoast SEO → Ajustes → Sitemaps y comprueba que están activados.
  2. Abre https://tu-dominio/sitemap_index.xml.
  3. Revisa los sitemaps de páginas, entradas, categorías y productos.
  4. Comprueba que no incluye URL con noindex ni parámetros basura.
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://tu-dominio/page-sitemap.xml</loc>
    <lastmod>2026-11-15T10:00:00+00:00</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://tu-dominio/post-sitemap.xml</loc>
  </sitemap>
</sitemapindex>

No necesitas crear manualmente otro sitemap si Yoast ya está generándolo. Duplicarlo solo crea dos archivos que pueden contradecirse.

Datos estructurados

WordPress, el tema y los plugins pueden generar datos estructurados automáticamente: información de la organización, del sitio, de los artículos, migas de pan y, en WooCommerce, del producto. Tu tarea es comprobar que existen, que son correctos y que no están duplicados por varios plugins.

Qué schema revisar
PáginaSchema esperadoDónde se genera
PortadaOrganization y WebSiteYoast, con los datos del sitio
EntradaArticle y BreadcrumbListYoast
ProductoProduct y OfferWooCommerce y/o Yoast
ReseñasReview y AggregateRatingWooCommerce, si hay reseñas reales
  1. Valida la portada y una entrada con Rich Results Test.
  2. Valida un producto con el validador de Schema.org.
  3. Busca dos bloques application/ld+json que describan lo mismo con datos distintos.
  4. Si el tema y Yoast generan el mismo schema, desactiva uno.

No inventes valoraciones

No añadas reseñas, estrellas, direcciones ni teléfonos que no existan. Google lo considera spam de datos estructurados y puede aplicar una acción manual. El schema debe describir lo que el usuario ve en la página.

16 Variaciones de producto y canonical

Un producto con colores no debería convertirse en diez páginas compitiendo.

Objetivo del paso

Configurar un producto variable y evitar que cada variación genere una URL indexable independiente.

En WooCommerce, un producto variable permite elegir atributos como color o talla. Las variaciones se seleccionan en la misma ficha y suelen añadir parámetros a la URL, por ejemplo ?attribute_pa_color=negro. Eso no debería crear una página nueva para cada combinación.

Cómo tratarlo
SituaciónQué hacer
Variaciones con parámetrosMantener una sola URL de producto y dejar que el selector cambie el precio y el stock.
Variación con URL propiacanonical a la ficha principal.
Variación con contenido muy distintoSolo entonces valorar una ficha independiente, con texto propio.
Variación agotadaMantener la ficha y avisar; no crear una URL nueva vacía.

Contenido duplicado y señales dispersas

Si cada variación tiene su propia URL indexable con el mismo texto, el buscador recibe varias páginas casi idénticas. Se reparte la autoridad y ninguna destaca. Una ficha principal con todas las opciones suele ser la mejor decisión.

Comprueba

  • El producto variable se muestra en una sola URL principal.
  • Cambiar de color no genera una página distinta en el índice.
  • El schema del producto incluye las variantes como offers cuando corresponde.

Evidencia

Captura del producto variable, de sus atributos y de la URL resultante al cambiar de variación.

17 Categorías de producto y filtros

Los filtros son cómodos para el usuario y peligrosos para el índice si no se controlan.

Objetivo del paso

Escribir categorías con contenido único y decidir qué hacer con las URL que generan los filtros y facetas.

Categorías de producto

Una categoría no es solo una lista de productos. Un buen texto descriptivo aporta contexto y contenido único para posicionar la categoría, además de ayudar al usuario a entender qué encontrará. 

H1  Portátiles para estudiar y trabajar
    Párrafo: qué tipos hay, para quién son y cómo elegir
    H2 Portátiles ligeros
    H2 Portátiles para diseño
    H2 Preguntas frecuentes
    Enlaces: guía de compra, servicio de puesta a punto
  • Escribe al menos dos párrafos por categoría principal.
  • No repitas el mismo texto en todas las categorías.
  • Enlaza la categoría con la guía del blog y con los servicios relacionados.
  • Configura título SEO y meta description propios desde Yoast.

Filtros y facetas

Los filtros por atributo, precio o etiqueta pueden generar muchas URL con parámetros y contenido duplicado. Por ejemplo: /portatiles/?filter_marca=lenovo&filter_ram=16gb. Si el buscador rastrea todas las combinaciones, desperdicia crawl budget y encuentra páginas casi idénticas.

Estrategias según el tipo de filtro
FiltroRecomendación
Filtros con valor de búsqueda realCrear una URL limpia y una landing con contenido propio.
Combinaciones infinitasnoindex o bloqueo de parámetros; canonical a la categoría base.
Ordenación y vistaNo indexar; son variantes de la misma lista.
Filtros de sesión o de usuarioNo indexar y evitar que se enlacen internamente.

No bloquees CSS ni JavaScript

Si usas robots.txt para bloquear filtros, revisa que no bloqueas las carpetas de estilos o scripts. Google necesita renderizar la página para evaluarla. Bloquear recursos críticos empeora la evaluación móvil.

Autoevaluación

Responde antes de desplegar la respuesta. Si fallas, vuelve al paso indicado.

¿Por qué no basta con configurar el título y el lema del sitio?

Porque el título y el lema son globales, pero cada página compite por una intención distinta. Si todas comparten el mismo título y la misma descripción, el buscador no puede distinguirlas y baja el CTR. Cada página necesita su propio title, meta description y contenido. Ver pasos 5 y 6.

¿Cuándo conviene aplicar noindex a una etiqueta?

Cuando el archivo de etiqueta tiene una sola entrada o muy poco contenido y no aporta una navegación real. En ese caso genera una página fina que compite con el blog. También puedes eliminar la etiqueta y evitar el problema desde el origen. Ver paso 8.

¿Se debe poner noindex a las páginas 2, 3… del blog?

Normalmente no. Si son el único camino hacia entradas antiguas, deben seguir siendo rastreables. Lo correcto es que cada página paginada tenga su propio canonical y enlaces claros. El desplazamiento infinito sin paginación real sí es un problema. Ver paso 9.

Un producto con diez colores, ¿debe tener diez URL indexables?

No. Las variaciones suelen compartir texto, imágenes y estructura, así que diez URL casi idénticas dispersan señales y generan duplicados. Lo habitual es una ficha principal con selector de variante y canonical a esa URL. Solo tendría sentido separar si el contenido fuese realmente distinto. Ver paso 16.

¿Por qué no se indexan el carrito ni el checkout?

Porque son páginas dinámicas, privadas o vacías para un visitante que llega desde Google. No aportan contenido y pueden mostrar estados distintos en cada sesión. Se marcan con noindex, no con un bloqueo en robots.txt. Ver paso 14.

¿Basta con instalar un plugin de caché para arreglar el rendimiento?

No. La caché ayuda, pero no reduce una imagen de 4 MB ni elimina un tema que carga sliders y fuentes innecesarias. Primero hay que identificar el problema con Lighthouse y actuar sobre imágenes, plugins, tema y recursos críticos. Ver paso 13.

Acabas de publicar la tienda y no aparece en Google. ¿Qué miras primero?

Que no quede activo noindex ni la opción «Desanimar a los motores de búsqueda». Es el error más habitual al pasar de local a producción. Después: HTTPS, URL correctas, sitemap enviado y estado en Search Console. Ver pasos 2 y 19.
